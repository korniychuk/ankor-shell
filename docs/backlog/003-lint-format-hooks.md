# 003 — Линтеры, форматтеры, pre-commit hooks, CI

## Задача
Ввести автоматический контроль качества: ShellCheck + shfmt, запуск на pre-commit и в CI. Сейчас в репозитории нет ни одного линтера, CI и git-хуков (только `.editorconfig`, у которого закомментирован `root = true`).

## Желаемый результат
- `.shellcheckrc` с продуманным набором правил (учесть: sourced-библиотека, bash+zsh, существующие inline-директивы в `node-loader.sh`, `cals.sh`, `config.sh`).
- shfmt-конфиг, согласованный с конвенциями (002): 2 пробела, стиль скобок, `[[ ]]`.
- Pre-commit hook: линт+формат только staged `*.sh` файлов. Механизм — `core.hooksPath` + свой bash-скрипт (без Node/Python зависимостей) или lefthook; выбрать и обосновать.
- GitHub Actions workflow: shellcheck + shfmt --diff на push/PR.
- Раскомментирован `root = true` в `.editorconfig`.
- Baseline: существующие нарушения либо исправлены (тривиальные), либо подавлены точечно с TODO-ссылкой на задачу 009 (style sweep) — хук не должен блокировать работу до завершения 009.

## Контекст / зацепки
- ShellCheck-смеллы уже известны: SC2059 (`printf` с переменным форматом, `sdk/str.sh:32,66`), unquoted expansions (`sdk/shell.sh:156,249,277,299`), `eval` на вычисляемом диапазоне (`sdk/str.sh:32`).
- `custom-scripts/` — отдельный вложенный git-репозиторий: хук основного репо его не касается; линт для него — отдельный вопрос.

## Открытые вопросы
- shfmt может конфликтовать с ручным выравниванием таблиц/heredoc — прогнать пробный `--diff` и решить объём принудительного форматирования.
- Линтить ли `local-scripts/` и `examples/` тем же профилем или ослабленным?
