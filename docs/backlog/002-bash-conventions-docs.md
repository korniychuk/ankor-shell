# 002 — Конвенции Bash: guidelines-доки + обновление CLAUDE.md

## Задача
Завести канонический документ конвенций Bash для репозитория (`docs/guidelines/bash-style.md`) и переработать `CLAUDE.md` так, чтобы оба описывали один и тот же стандарт. Это фундамент для линтеров (003), style-sweep (009) и генератора документации (00a).

## Желаемый результат
- `docs/guidelines/bash-style.md` в стиле reference-manual: Scope → Requirements (MUST-list) → канонический шаблон скрипта → справочник utilities → конвенции переменных → формат doc-комментариев → exit-коды → emoji-словарь вывода.
- Канонизирован формат doc-комментариев (сейчас плавает): выбрать единые теги (`@param` vs `@arg`, `@output` vs `@stdout`), единый ограничитель (`##`), единый регистр типов (`{string}`), единый маркер обязательности. Канон обязан быть парсибельным генератором доков (00a).
- Зафиксированы: naming (camelCase, без дефисов в новых функциях), дисциплина `local -r`/`declare -r/-ri/-rx/-a/-A`, `[[ ]]` вместо `[ ]`/`test`, quoting, схема exit-кодов (0/1/10/11/12–19/20+).
- Секция «CaLS-инварианты» — что нельзя ломать: имена `aks.*`/`akl.*`, `.bin/` на PATH, env-переменные `AK_CALS_PATH`/`AK_CALS_DIR`/`AK_CALS_COMMAND` в обёртках, GC stale-обёрток по префиксу, overridable `AK_CALS_*_PATH`.
- `CLAUDE.md` обновлён: ссылка на guidelines, инструкция использовать `ak.sh.ok/warn/err/die` вместо raw echo, схема exit-кодов, CaLS-инварианты.

## Контекст / зацепки
- Структура и тон документа — по образцу проверенного guideline-дока из reference-библиотеки; выжимка портируемых практик: `ankor/hardening-ref-notes.md` (локально, не коммитится).
- Текущие расхождения формата doc-комментариев задокументированы там же (примеры: `sdk/str.sh:12`, `sdk/shell.sh:80`).
