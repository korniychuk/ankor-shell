# 004 — Smoke-тесты: защита рефакторинга

## Задача
Перед масштабным рефакторингом (005–009) завести минимальный тестовый каркас, чтобы не сломать загрузку библиотеки и CaLS. Сейчас тестов нет вообще.

## Желаемый результат
- Выбран подход: bats-core vs минималистичный собственный раннер `*.spec.sh` (плоские скрипты, где assert-модуль (006) сам является test-framework'ом; раннер — find + запуск каждого spec в чистом `bash`, счёт падений). Второй вариант — zero-dependency и совпадает с философией библиотеки; обосновать выбор.
- Smoke-тесты: `index.sh` сорсится без ошибок в bash И в zsh; ключевые функции определены; `cals.sh` генерирует обёртки с корректным содержимым (все CaLS-инварианты из 002 покрыты assert'ами); GC stale-обёрток работает; повторный source идемпотентен.
- Unit-тесты чистых функций: `ak.str.*`, `ak.array.*`, `ak.rnd.*` (детерминированные части), `ak.dt.*`.
- Запуск тестов включён в pre-commit hook и CI (003).

## Контекст / зацепки
- Образец минималистичного spec-раннера — в reference-библиотеке (см. `ankor/hardening-ref-notes.md`): «spec проходит ⇔ скрипт вышел с 0», ✅/❌ по файлу.
- CaLS-тесты должны работать во временном `$AK_SCRIPT_PATH`-песочнице (переопределяемость `AK_CALS_*_PATH` это позволяет), не трогая реальный `.bin/`.
