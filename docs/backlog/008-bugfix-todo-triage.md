## Желаемый результат
- Баги исправлены:
  - `ak.sh.isInteractive` (`sdk/shell.sh:332`) — `return [[ ... ]]` невалиден синтаксически;
  - `ak.sh.commandExists` (`sdk/shell.sh:168-174`) — нет явного success-пути, код возврата хрупкий;
  - **`ak.sh.type` (`sdk/shell.sh:48-57`) — ложный `unknown`, когда шелл запущен с аргументами.** Определение идёт через `ps -hp $$` + `sed -E 's/.*((z|ba|c|tc|k)sh)$/\1/'`: BSD `ps` (macOS) печатает полную командную строку, поэтому у `zsh -fc '…'` / `bash -c '…'` строка не оканчивается именем шелла и regex не совпадает → `unknown` → `ak.sh.isZsh`/`isBash` обе false. Плюс флаг `-h` (подавление заголовка) — GNU-only, BSD его игнорирует и печатает шапку. В живой интерактивной сессии (`-zsh`) совпадение случайно происходит, поэтому баг не виден. Правильный сигнал — `$ZSH_VERSION`/`$BASH_VERSION` (устанавливает сам шелл, соврать не может); `ps` оставить максимум как fallback. Найдено в 00b: из-за этого `completions/load.sh` молча не регистрировал автодополнения — там уже переведено на version-переменные (`bb139d2`), остальные call-sites `isZsh`/`isBash` (`sdk/git.sh`, `cals.sh`, …) нужно проверить и мигрировать;
  - `die`/`param.required` `exit` из интерактивной сессии (решается в 005, здесь — проверить все call-sites);
  - `printf` с переменным format-string (`sdk/str.sh:32,66,124`, SC2059) и `eval "echo {1..$n}"`;
  - unquoted expansions (`sdk/shell.sh:156,249,277,299`, `index.sh:50`);
  - cals.sh: обёртки не регенерируются при изменении шаблона/`AK_SCRIPT_PATH` (создаются только если файла нет) — добавить механизм инвалидации (версия/hash шаблона в обёртке); ветка missing-prefix только warn'ит без `return` (`cals.sh:31`); word-split в `find | for` циклах.
